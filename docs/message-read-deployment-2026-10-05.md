# 消息已读回执检查与修复

2026-10-05 功能提交 `9922fc8`、`90acc4f` 已推送 GitHub，部署到 `https://999.99chat99.com`。

## 检查结果与修复

- 原页面未监听 OpenIM `OnRecvC2CReadReceipt`，对方阅读后发送方缓存没有更新。
- 原页面仅在进入聊天时调用 `markConversationMessageAsRead`，持续接收消息时未继续上报。
- 现在按原生回执中的 clientMsgID 更新本人已发送消息；仅可见聊天在 SDK 同步完成后上报阅读。
- SDK 初始同步完成后重新读取历史，合并时保留原生历史和实时回执的已读状态，避免旧缓存覆盖。
- 未读数由原生会话及总未读事件更新，不再因切换会话提前清零或收到消息重复计数。
- 修正单聊消息的会话匹配，避免空 groupID 匹配到其他单聊。
- 单聊单勾表示发送成功但对方未读，蓝色双勾表示已读；图标增加对应辅助阅读标签。

OpenIM `markConversationMessageAsRead` 对单聊会发送已读回执；群聊只清理当前用户未读数。
群消息的勾现在只表示发送成功，不将单聊 isRead 误当成全体群成员已读；成员已读统计未实现。
「标记为未读」现有实现仍是本地会话提醒，刷新后消失，不会撤回已经发送的原生已读回执。
本次没有添加自定义跨端未读提醒。

## 验证

用户之前已确认使用独立账号创建持久测试消息。本次复用同一对独立账号，未使用用户账号。
原页面真实浏览器测试复现：接收方看到消息后，发送方未实时显示双勾。
最新部署版本 `message_read_e2e.cjs` 线上真实浏览器回归通过：

1. 接收方未打开聊天时，发送方保持单勾，接收方会话显示未读红点。
2. 打开聊天后，发送方实时变为双勾，接收方红点清除。
3. 持续停留聊天接收下一条消息，无需重新进入也能更新双勾。
4. 发送方刷新后，已读状态保留。
5. 接收方离开聊天后，新消息保持未读；重新打开后变成双勾。

服务端独立测试账号的 hasReadSeq 查询确认阅读状态已推进到 maxSeq。
可见性分支已加入检查；此次自动化验证覆盖离开聊天，未模拟操作系统后台运行。
本地 TypeScript / Vite 构建、线上 Docker 构建、Nginx 配置检查通过。
仅重建网页服务，OpenIM 配置和镜像保留；网页回滚镜像为 `chat-project-web:before-read-receipts`。
