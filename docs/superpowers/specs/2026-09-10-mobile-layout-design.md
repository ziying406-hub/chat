# 99chat 手机网页适配方案

## 目标与边界

补齐现有 React 网页的手机布局，沿用现有 OpenIM SDK、账号、消息、收藏与权限接口；不新增原生 App，不改服务器登录策略或数据模型。桌面多栏布局保持不变。本方案依据用户同意开始补齐单页切换、返回按钮及输入框/弹窗布局的范围整理，具体交互待用户审阅后实施。

## 方案选择

采用现有页面的响应式改造：保留组件和路由，按屏幕宽度、当前路由显示列表或详情。改动集中，桌面与手机共享业务逻辑。

不采用另建 H5 项目：独立设计更自由，但会重复维护消息、收藏和权限逻辑。不采用将桌面三栏简单缩小：触控区域、聊天可读性和键盘遮挡问题仍然存在。

## 页面规则

- 宽度不超过 768px 为单栏；超过 768px 保留现有桌面布局。
- `/messages` 只显示全宽会话列表。进入会话后只显示聊天页，隐藏列表与底部导航；返回按钮回到会话列表。
- `/contact` 显示全宽通讯录。联系人、群组、申请、搜索与群管理等详情独占一屏，提供返回所属上级页面的入口。
- 手机 `/settings` 显示个人中心菜单和账号信息；点击资料、收藏、通知等进入单屏详情。桌面 `/settings` 继续默认展示资料编辑。手机个人中心保留资料、二维码等原有入口，不删功能。
- 底部“消息／通讯录／设置”仅在三个根页面显示，计数沿用现有状态；详情页通过返回按钮回到上级。无历史的直接链接也能返回明确父路由，不依赖无条件 `history.back()`。
- 会话设置返回会话；设置中的媒体与搜索返回会话设置；收藏详情返回收藏列表；群管理返回相应群详情或会话。既有业务返回入口复用，不重复叠加标题栏。

## 布局与输入

- 使用专用页面类管理手机高度、滚动和安全区域，移除影响所有 `.flex.h-screen` 的泛用补白规则。
- 列表、聊天记录及长表单在各自内容区域滚动；页面不产生横向滚动。聊天输入区不被底部导航覆盖。
- 优先采用动态视口高度与安全区域补白。若实测发现软键盘缩小可视区域后仍遮挡输入区，使用一个局部视口监听处理，不散布到各业务组件。
- 手机消息气泡、图片、视频和文件卡片按可用宽度约束；工具栏可换行或横向滚动，发送按钮保持可点击。
- 弹窗宽度不超过屏幕，长内容内部可滚动，确认/关闭操作可触达。保留现有字段验证和上传/发送错误提示。
- 手机触控返回及主要操作区域至少约 44px；不依赖悬停才能进行必要操作。

## 组件与状态

`MainLayout` 负责根导航与可视区域；会话列表、通讯录、设置容器负责路由对应的列表/详情显示；聊天页负责消息区域及输入区约束。必要时增加一个小型共享手机返回组件，父路由明确传入。

不重复初始化 SDK；切换布局不清空账号状态、消息、未读数和草稿。页面刷新继续走现有会话恢复。桌面调整仅限为手机布局增加类名或明确容器边界，不做无关重构。

## 验收

1. 先用浏览器测试记录旧版手机列表/详情并列、横向溢出或输入区遮挡的失败断言，再验证改动。
2. 375px、390px、430px 下检查会话、通讯录、设置根页面和详情的单屏切换、返回、无横向溢出；1280px 下检查桌面仍为原有多栏。
3. 独立测试账号与桌面端进行真实文字收发，手机刷新后历史可见；打开图片/收藏详情及群设置，确认操作入口可达且权限未改变。
4. 检查输入聚焦、缩小可视区域、滚动到底部及弹窗长内容。浏览器模拟不等同真实手机键盘；没有实体 iPhone/Android 证据时明确标注该项未实机验收。
5. 构建、相关回归通过后，更新开发/产品/验证文档，提交 Git；保留生产前端回滚镜像后部署，再验证线上页面。不能以构建成功代替手机交互通过。

## 风险与回滚

重点防止路由切换隐藏错误面板、返回死路、键盘遮挡和桌面布局退化。所有变化在前端；回滚前端镜像即可，不回滚或删除聊天数据，不重启 OpenIM。
