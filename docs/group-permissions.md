# 群权限规则

2026-09-10 用户确认，按 OpenIM 群主、管理员、普通成员区分权限。

| 操作 | 群主 | 管理员 | 普通成员 |
|---|---|---|---|
| 查看群资料与公告 | 可 | 可 | 只读 |
| 修改头像、名称、公告、简介 | 可 | 可 | 不可 |
| 入群方式、入群申请审核 | 可 | 可 | 不显示管理控件 |
| 邀请成员 | 可 | 可 | 按群入群规则 |
| 禁言、移除普通成员 | 可 | 可 | 不可 |
| 管理其他管理员 | 可 | 不可 | 不可 |
| 设置或取消管理员 | 可 | 不可 | 不可 |
| 转让群主（含转给管理员）、解散 | 可 | 不可 | 不可 |
| 自己的群昵称、免打扰 | 可 | 可 | 可 |
| 退出 | 先转让；另有解散入口 | 可 | 可 |

共享前端规则在 `99chat/src/utils/group-permissions.ts`。
普通成员的群名称、公告和简介使用纯文本展示，不渲染输入框或文本编辑区，
无保存、换头像、申请审批或禁言按钮。空公告、简介显示对应空状态；
降级为普通成员后，展示已保存的群资料，不展示未保存的编辑草稿。
头像快捷入口与管理设置使用同一规则；角色变更通知刷新成员权限，群信息通知刷新群主和资料。
前端限制只是交互控制，服务端权限校验不可省略。

共用 store 操作在调用 SDK 前读取当前群和成员权限，覆盖资料编辑、邀请、移除、
禁言、审批、管理员设置、转让、解散与退出；各页面退出统一走同一操作。
退出、解散及群删除通知会清除该群和成员权限缓存，迟到的成员查询不会恢复已退出群的缓存。
聊天邀请入口也使用共享规则。此检查不能替代服务端鉴权，尚未完成全部接口的越权审计。

OpenIM `needVerification` 实际值：

- 0：申请需要审批，邀请直接入群。
- 1：申请和邀请均需审批（群主/管理员邀请按 OpenIM 特权规则处理）。
- 2：无需审批入群。不是“禁止入群”，原界面文案已纠正。

没有新增“禁止入群”后端能力，也没有修改生产群的当前入群设置。

## 验证

在本地真实 OpenIM 测试环境执行：

```sh
cd 99chat
node group_permissions_test.mjs
node group_permissions_e2e.cjs
node group_application_e2e.cjs
node group_invite_e2e.cjs
node group_quit_e2e.cjs
node avatar_upload_e2e.cjs
npm run build
```

权限联调创建独立测试群，验证普通成员直接访问审批路由不会得到审批界面、
直接调用 SDK 修改群资料被权限拒绝、提升管理员后编辑持久化、降级后权限撤销。
同时验证共用操作拒绝普通成员修改、转让群主给管理员、旧群主退出后旧管理路由失效，
以及退出后共用邀请操作被拒绝。
权限单测覆盖管理员不能管理同级与群主、群主可以管理管理员、未加载身份不误判为群主。
这些测试不代表所有群操作、所有异常路径都已逐项完成全量验收。
